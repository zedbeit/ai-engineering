How AI assistants were used on this project, what they produced and how their output was checked.

Format from week 3 on: date | task given to the agent | what it did | what I rejected or changed | why.

## 2026-11-16: SPEC.md breakdown

Tool: Claude Code in the terminal.

### What the AI did

- **Breakdown of `SPEC.md`.** I asked Claude to break down the spec for the intake service. It listed the sections the spec needs and the decisions I have to make in each one (id type, validation limits, search behaviour, status codes, error shape, database location). It did not write any of the spec.
- **Design decisions, made together.** Claude asked eleven multiple-choice questions (id type, title and text rules, search behaviour, list shape, pagination, validation status, extra fields, database location, database library), each with a recommendation. I chose the recommended option every time. Claude also proposed defaults I did not choose between: `201` for create, `204` for delete, `404` body `{"detail": "Document not found"}`, list ordered by id, ids never reused.
- **`SPEC.md` skeleton.** Claude created the headings and wrote section 3.4 (`DELETE /documents/{id}`) in full as a worked example. Everything else was `TODO`.
- **All of `SPEC.md`.** I asked Claude to fill in the whole draft, and it wrote every section from the decisions above; I wrote none of the wording. The curriculum says to write the spec yourself, so this is a departure from it. Claude also added details I had not decided: `text` is stored untrimmed; the timestamp is to the second and ends in `Z`; `%` and `_` in a search term are literal; search ignores case for A to Z only; one database connection per request, with the table created on connect; the app lives at `intake_service.main:app`; tests assert the `422` status and not its wording.
- **Project setup.** Claude ran `uv init --package`, added FastAPI, Uvicorn, pytest, httpx, mypy and ruff, and copied the mypy, ruff and pytest settings from `async-fanout`. It wrote `src/intake_service/main.py` as an empty app (`app = FastAPI()`, no routes) so that the tests fail on behaviour and not on a missing import.
- **Test skeleton.** Claude wrote `tests/conftest.py` (the `db_path` and `client` fixtures) in full, the names of all 31 tests, and six test bodies: one worked example each in `test_create.py`, `test_get.py`, `test_list.py` and `test_delete.py`, the `create` helper in `test_list.py`, and all of `test_persistence.py`. The other 25 bodies are `raise NotImplementedError`. All 31 fail; mypy and ruff pass.
- **All the test bodies.** I asked Claude to fill in the 25 placeholder tests, and it wrote every one; I wrote none of the tests. The curriculum says to write the tests yourself, so this is a second departure from it. Claude also added things I had not asked for: eleven more invalid-input cases (null and non-string values, whitespace-only text), `test_create_rejects_a_body_that_is_not_an_object`, a `search_ids` helper, and a `create` helper in `test_delete.py`. Result: 43 tests, all failing against the empty app because the routes return 404; mypy and ruff pass.
- **`AGENTS.md` and `CLAUDE.md`.** I asked Claude to write the agent instructions after it broke the step down. It wrote all of `AGENTS.md` (commands, "never edit `tests/` or `SPEC.md`", no new dependencies, code rules, layout, working one endpoint at a time, what done means) and a one-line `CLAUDE.md` that imports it. The curriculum lists this as mine to write. Claude added two rules I had not asked for: never special-case a test to make it pass, and no `Any` or `# type: ignore` without a reason.
- **The pytest hook and the permission rule (step 4).** I asked Claude for step 4 and it wrote both without a breakdown first. `.claude/hooks/run-pytest.sh` runs `uv run pytest -q --tb=no` after any edit to a `.py` file and, if tests fail, sends the list of failing tests back to the agent (exit code 2). `.claude/settings.json` registers it as a `PostToolUse` hook on `Write|Edit` and denies edits to `tests/` and `SPEC.md`. Claude checked both in the session: an edit to `main.py` came back with the 43 failures, and an edit to `tests/test_get.py` was refused. The curriculum lists this step as mine.
- **Baseline commit.** On my choice ("commit on main"), Claude committed the `intake-service/` folder as `3c1b93f`: spec, 43 failing tests, `AGENTS.md`, hook, empty app.
- **Step 5, `POST /documents`.** Task given: implement step 5. Claude implemented the first endpoint only and stopped for my review. New files `src/intake_service/models.py` (Pydantic models and the title and text rules) and `src/intake_service/db.py` (`connect`, `insert_document`); `main.py` gained the route. Result: 21 of 43 tests pass (all of `test_create.py` except `test_create_stores_nothing_when_rejected`, which needs `GET /documents`); mypy and ruff pass; `tests/` and `SPEC.md` unchanged. Not yet reviewed by me.
- **Step 5, `GET /documents/{id}`.** I said "next" after the first endpoint. Claude added `get_document` to `db.py` and the route to `main.py`, raising `HTTPException(404, "Document not found")` for a missing id. Result: 25 of 43 tests pass (all of `test_get.py` and `test_persistence.py` are now green); mypy and ruff pass; `tests/` and `SPEC.md` unchanged.
- **Step 5, `DELETE /documents/{id}`.** I said "go ahead". Claude added `delete_document` to `db.py` (returns whether a row was deleted) and the route to `main.py` with status 204, raising the same 404 when nothing was deleted. Result: 31 of 43 tests pass; the 12 still failing all call `GET /documents`; mypy and ruff pass; `tests/` and `SPEC.md` unchanged.
- **Step 5, `GET /documents` (list and search).** I said "go ahead with the list endpoint". Claude added `DocumentSummary` to `models.py`, `escape_like` and `list_documents` to `db.py`, and the route to `main.py`. Result: all 43 tests pass; mypy, ruff check and ruff format pass; `tests/` and `SPEC.md` unchanged. Claude also started the service with Uvicorn and sent real requests with `curl` (create, search, a `%` search, a bad id, delete, fetch after delete); all gave the responses in the spec. Nothing from step 5 is committed, and I have not yet recorded a review of any of the four endpoints.
- **Verification step: the `verifier` subagent.** I asked how an agent can verify the work beyond passing tests. Claude proposed goals for the project and wrote `.claude/agents/verifier.md`: a subagent with a fresh context that gets the spec, code and tests but not the implementer's explanation. It may read files and run commands but must not change anything in the project. It runs the automatic checks, maps every spec requirement to code and test, puts deliberate bugs into a copy of the project to see whether a test catches each one, sends real requests to a running service, and reports evidence per requirement and per goal. Claude also drafted a Goals section for `SPEC.md` for me to edit and paste in, since it can't edit that file.
- **First verifier run.** After I pasted the Goals section into `SPEC.md`, I asked Claude to verify. It ran the `verifier` subagent; the run made no changes to the project. All 43 tests, mypy and ruff passed, and all 30 or so real requests matched the spec except one: a valid id too big for SQLite (`/documents/99999999999999999999`) gives `500` instead of `404` on GET and DELETE. Claude reproduced that one itself before reporting. Four deliberate bugs left every test green: no `ORDER BY` in search, `ORDER BY id DESC` in search, search term trimmed, backslash not escaped. Goals: correct FAIL, protected FAIL, real PASS, extendable PASS, clean PASS, understood left to me. Nothing fixed yet.
- **Fixing the verifier findings.** I chose `404` for ids too large for SQLite and told Claude to lift the deny rule on `tests/` and `SPEC.md`, make the changes, and restore it. Claude added one sentence to the `404` row in `SPEC.md` section 4 (zero, negative and too-large ids are `404`) and wrote 12 new test cases: 4 id cases each for GET and DELETE, search ordering with several matches, an untrimmed search term, a backslash search, and a title length counted in characters. The 4 too-large-id cases failed with the `OverflowError`; the rest passed. In a copy of the project, Claude checked that the new tests catch the bugs the verifier had planted: search ordered `DESC`, search trimmed, backslash not escaped. Removing `ORDER BY` from the search still passes, because SQLite returns this table in id order anyway, so that bug can't be seen from outside. Claude then restored the deny rule (no diff in `settings.json`) and fixed `db.py`: `get_document` and `delete_document` return "not found" for ids beyond SQLite's 64-bit range before running the query. Result: 55 tests pass; mypy and ruff pass.
