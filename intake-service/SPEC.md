# Document intake service: specification

## Goals

What this version must achieve. The verifier checks each one.

1. **Correct:** every rule in this spec holds, shown by a test or by a real request.
2. **Protected:** breaking any rule in this spec makes at least one test fail.
3. **Real:** it runs under Uvicorn, answers real HTTP requests, and keeps its
    data across a restart.
4. **Extendable:** adding `POST /documents/{id}/extract` needs a new route and
    new code, with no rewrite of what is here.
5. **Understood:** I can explain every line of `src/` without help.
6. **Clean:** strict mypy and ruff pass, and there are no dependencies beyond
    those in section 6.

## 1. Purpose and scope

The intake service is a small HTTP API that stores text documents. A client can
create a document from a title and its text, fetch one document by id, list or
search the stored documents, and delete one. Documents are kept in a SQLite
database and survive a restart.

Out of scope for this version:

- Authentication and users. Every client can see and delete every document.
- File uploads. A document arrives as JSON text, not as a PDF or image.
- Updating a document. There is no `PUT` or `PATCH`.
- Pagination. The list returns every match.
- Any call to an LLM. A later project adds `POST /documents/{id}/extract`;
  nothing here should be built for it yet.

## 2. Data model

A document has these fields:

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Generated by the database, starting at 1. Never reused, even after a delete. |
| `title` | string | Required. Leading and trailing whitespace is removed before validating and storing. 1 to 200 characters after that. |
| `text` | string | Required. Must contain at least one non-whitespace character. At most 100,000 characters. Stored exactly as sent, without trimming. |
| `created_at` | string | Set by the server when the document is created; a client cannot set it. UTC, ISO 8601, to the second, ending in `Z`: `2026-11-16T09:30:00Z`. |

Lengths are counted in characters, not bytes.

Two documents may have the same title, and the same text. Each gets its own id.

The API returns a document in two shapes:

- **Full document:** `id`, `title`, `text`, `created_at`.
- **Summary:** `id`, `title`, `created_at`. No `text`.

## 3. Endpoints

All request and response bodies are JSON.

### 3.1 `POST /documents`

Creates a document.

- **Request body:** an object with `title` and `text`, both strings. Any other
  field in the body is ignored (including `id` and `created_at`).
- **Success:** `201 Created`. The body is the full document as stored, so the
  `title` is the trimmed one.
- **Errors:** `422`, FastAPI's default validation response, when:
  - `title` or `text` is missing, `null`, or not a string;
  - `title` is empty or only whitespace;
  - `title` is longer than 200 characters after trimming;
  - `text` is empty or only whitespace;
  - `text` is longer than 100,000 characters;
  - the body is not a JSON object.
- Nothing is stored when the request is rejected.

### 3.2 `GET /documents/{id}`

Returns one document.

- **Request:** no body. `id` is an integer in the path.
- **Success:** `200 OK`. The body is the full document.
- **Errors:**
  - No document has that id: `404` with `{"detail": "Document not found"}`.
  - `id` is not an integer (for example `abc`): `422`, FastAPI's default
    validation response.

### 3.3 `GET /documents?search=`

Lists documents, optionally filtered by a search term.

- **Request:** no body. `search` is an optional query parameter.
- **Success:** always `200 OK`. The body is a JSON array of summaries, ordered
  by `id` ascending (oldest first).
- **Without `search`, or with an empty one (`?search=`):** every document is
  returned.
- **With `search`:** a document is returned if the term appears anywhere in its
  `title` or anywhere in its `text`.
  - The match is a substring match: `rent` matches `Rent receipt` and
    `current account`.
  - Upper and lower case are treated as the same for the letters A to Z.
  - The term is used exactly as sent; it is not trimmed.
  - `%` and `_` in the term are ordinary characters, not wildcards:
    `?search=100%` only matches documents containing `100%`.
- **No matches, or no documents at all:** `200 OK` with `[]`. Never `404`.
- **Errors:** none.

### 3.4 `DELETE /documents/{id}`

Deletes one document permanently.

- **Request:** no body. `id` is an integer in the path.
- **Success:** `204 No Content`, with an empty body.
- **Errors:**
  - No document has that id: `404` with `{"detail": "Document not found"}`.
    This includes deleting the same id a second time.
  - `id` is not an integer (for example `abc`): `422`, FastAPI's default
    validation response.
- **After a successful delete:** `GET /documents/{id}` returns `404`, and the
  document no longer appears in `GET /documents`. Its id is never reused.

## 4. Error responses

Every error body is a JSON object with one key, `detail`. The service returns
only the two errors below and does not change FastAPI's default error format.

| Status | When | Body |
|---|---|---|
| `404` | The id in the path is a valid integer, but no document has it. This includes zero, negative ids and ids too large for the database to store, such as `99999999999999999999`. | `{"detail": "Document not found"}` |
| `422` | The request is invalid: a bad body on `POST`, or an id that is not an integer. | FastAPI's default: `{"detail": [ ... ]}`, a list with one entry per problem. |

Tests check the status code for `422`, not the exact wording inside `detail`.

## 5. Storage

- **Database:** SQLite, through Python's standard-library `sqlite3` module. No
  ORM and no other database library.
- **Location:** the path in the `INTAKE_DB_PATH` environment variable. If it is
  not set, `./intake.db` in the folder the service is started from.
- **Table:**

  ```sql
  CREATE TABLE IF NOT EXISTS documents (
      id         INTEGER PRIMARY KEY AUTOINCREMENT,
      title      TEXT NOT NULL,
      text       TEXT NOT NULL,
      created_at TEXT NOT NULL
  );
  ```

  `AUTOINCREMENT` is what stops an id being reused after a delete.
- **Connections:** each request opens its own connection and closes it when the
  request ends. `INTAKE_DB_PATH` is read each time a connection is opened, not
  when the module is imported. The table is created if it does not exist each
  time a connection is opened, so the service works against a new, empty file
  with no setup step.
- **SQL values:** always passed as `?` parameters, never built into the SQL
  string.
- **Persistence:** documents are still there after the service is stopped and
  started again with the same `INTAKE_DB_PATH`.
- **Tests:** each test sets `INTAKE_DB_PATH` to a new file in a temporary
  folder before making requests, so every test starts with an empty database
  and no test touches `./intake.db`.

## 6. Constraints

- Python 3.12 or newer.
- FastAPI, with Pydantic models for every request and response body.
- Uvicorn as the server: `uv run uvicorn intake_service.main:app`.
- uv for the project and its dependencies; one `pyproject.toml` in
  `intake-service/`.
- Layout:
  - `src/intake_service/`: the package. The FastAPI app is the object `app` in
    `src/intake_service/main.py`.
  - `tests/`: pytest tests using FastAPI's `TestClient` (which needs `httpx` as
    a development dependency).
- Type hints on every function. `uv run mypy src tests` passes with
  `strict = true`.
- `uv run ruff check` and `uv run ruff format --check` pass, with the same lint
  rules as the other projects in this repo: `E`, `F`, `I`, `B`, `UP`.
- `uv run pytest` passes.
- No dependencies beyond FastAPI, Uvicorn and the development tools above.

## 7. Examples

One request and response per behaviour. Each one becomes at least one test.

**Create a document**

```
POST /documents
{"title": "  Receipt 14  ", "text": "Rent for November: 250,000"}

201
{"id": 1, "title": "Receipt 14", "text": "Rent for November: 250,000", "created_at": "2026-11-16T09:30:00Z"}
```

**Create with extra fields: ignored**

```
POST /documents
{"title": "Receipt 15", "text": "Fuel", "author": "Dee", "id": 99}

201
{"id": 2, "title": "Receipt 15", "text": "Fuel", "created_at": "2026-11-16T09:31:00Z"}
```

**Create with invalid input: each of these is rejected**

```
POST /documents   {"text": "Fuel"}                       -> 422  (no title)
POST /documents   {"title": "   ", "text": "Fuel"}       -> 422  (whitespace-only title)
POST /documents   {"title": "a" * 201, "text": "Fuel"}   -> 422  (title too long)
POST /documents   {"title": "Receipt"}                   -> 422  (no text)
POST /documents   {"title": "Receipt", "text": ""}       -> 422  (empty text)
POST /documents   {"title": "Receipt", "text": "a" * 100001} -> 422  (text too long)
POST /documents   {"title": 123, "text": "Fuel"}         -> 422  (title not a string)
```

A title of exactly 200 characters and a text of exactly 100,000 characters are
both accepted with `201`.

**Fetch a document**

```
GET /documents/1

200
{"id": 1, "title": "Receipt 14", "text": "Rent for November: 250,000", "created_at": "2026-11-16T09:30:00Z"}
```

**Fetch a missing document**

```
GET /documents/999

404
{"detail": "Document not found"}
```

**Fetch with a bad id**

```
GET /documents/abc

422
```

**List everything** (documents 1 and 2 exist)

```
GET /documents

200
[
  {"id": 1, "title": "Receipt 14", "created_at": "2026-11-16T09:30:00Z"},
  {"id": 2, "title": "Receipt 15", "created_at": "2026-11-16T09:31:00Z"}
]
```

**Search: matches the text, ignoring case**

```
GET /documents?search=RENT

200
[{"id": 1, "title": "Receipt 14", "created_at": "2026-11-16T09:30:00Z"}]
```

**Search: matches the title**

```
GET /documents?search=receipt 15

200
[{"id": 2, "title": "Receipt 15", "created_at": "2026-11-16T09:31:00Z"}]
```

**Search: no matches**

```
GET /documents?search=salary

200
[]
```

**Search: `%` is not a wildcard**

```
GET /documents?search=%

200
[]
```

**Delete a document, then delete it again**

```
DELETE /documents/1   -> 204, empty body
GET /documents/1      -> 404 {"detail": "Document not found"}
DELETE /documents/1   -> 404 {"detail": "Document not found"}
```

**Ids are not reused** (after the delete above, with document 2 as the newest)

```
POST /documents
{"title": "Receipt 16", "text": "Data bundle"}

201
{"id": 3, ...}
```

**Documents survive a restart**

Create a document, stop the service, start it again with the same
`INTAKE_DB_PATH`: `GET /documents/{id}` still returns it.
